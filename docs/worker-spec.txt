Implement self-hosted Local Speedtest for Debian Linux with LibreSpeed Go backend, SQLite telemetry, and HTML5 frontend.

Read the project documentation first:
- docs/requirements.md
- docs/design.md
- docs/tasks.md
- docs/CONTEXT.md

Requirements to implement:
1. Directory structure: config/, data/, systemd/, web/, scripts/, tests/
2. LibreSpeed Go configuration (config/settings.toml):
   - Bind to 0.0.0.0:8989 (or configurable port)
   - Enable SQLite telemetry (data/telemetry.db)
   - Enable result sharing with unique ID / hash
   - Configure assets path to web/
3. Setup and download script (scripts/install.sh):
   - Detects architecture (amd64/arm64)
   - Downloads official release binary of librespeed/speedtest-go
   - Makes binary executable and sets up directories
4. Frontend assets (web/):
   - Clean, lightweight HTML5 speedtest interface
   - Pre-configured telemetry endpoint to save results to backend
   - Share button displaying shareable link for completed tests
   - Results view (/results/?id=...)
5. Systemd unit template (systemd/local-speedtest.service):
   - Parameterized with @APP_DIR@ and @APP_USER@ (matching MRTG-CMP pattern)
   - Restarts on failure, runs as background daemon
6. Production deploy script (deploy.sh):
   - Follows the pattern in MRTG-CMP/deploy.sh
   - Handles dependency check, directory prep, systemd unit sed templating, daemon-reload, enable, restart, and health verification
7. Automated verification tests (tests/):
   - Test script (e.g. tests/test_local_speedtest.py or bash) to verify HTTP endpoints (health, speedtest telemetry, results rendering)
8. Comprehensive README.md:
   - Architecture overview
   - Cloudflare Grey Cloud (DNS Only) A-record setup guide for speedtest.mriazh.my.id
   - Local deployment instructions on Debian (~/Github-PC/Local-Speedtest)
   - Result sharing explanation
